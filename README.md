# تساهيل
تطبيق ويب عربي للجوال يجمع تجربة شمال AI مع دورة الطلبات المستلهمة من تصريح: فهم الاحتياج → تجهيز الطلب والمرفقات → مراجعة المستفيد → توجيه للجهة → استكمال / رد / قرار → وثيقة تجريبية.

## التشغيل
يتطلب Node.js 22+ و pnpm 11.
```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm build
pnpm start
```

## تجربة الطرفين
بدون DATABASE_URL يعمل النظام محلياً في المتصفح. من صفحة الدخول اختر «الدخول كمستفيد تجريبي». قدّم طلباً، ثم من «حسابي» اختر الجهة المطابقة و«الدخول كموظف الجهة التجريبي». جرّب طلب الاستكمال والرد، أو موافقة وإصدار تجريبي لترخيص/تصريح. حساب «إشراف المنصة التجريبي» يعرض جميع الجهات والتصعيد.
البيانات التجريبية مشتركة بين الحسابات في نفس المتصفح فقط؛ ليست تخزيناً متعدد الأجهزة ولا نظام مصادقة حقيقياً. لا تستخدم بيانات شخصية حقيقية في هذا الوضع.

## ما تم دمجه
- الحفاظ على الهوية البصرية والرحلات وقاعدة المعرفة والمساعد في شمال، مع تغيير الاسم إلى تساهيل وتوسيع النطاق إلى مناطق السعودية الـ13.
- نقل مفاهيم التوجيه، الحالات، سجل الإجراءات، الفصل بين المستفيد والجهة، المدة المستهدفة والتصعيد من تصريح إلى نموذج طلبات موحد داخل Next.js.
- إضافة أنواع الاستفسار وترخيص النشاط والتصريح؛ حسابات الجهات للاستقبال والرد فقط.
- المرفقات تحفظ محتوى الملف، مع حدود خمسة ملفات، 750 كيلوبايت لكل ملف وإجمالي 2 ميجابايت.
- فحص PDF النصي (حتى أول عشر صفحات) وTXT، وتحليل المحتوى عند ضبط مزود ذكاء اصطناعي. الصور تتطلب مزوداً متوافقاً يدعم الرؤية (OpenAI-compatible أو Anthropic). PDF الممسوح بلا طبقة نص يحتاج مراجعة بشرية؛ لا توجد OCR مدمجة له.
- توقيع الوثيقة الرسمي والتحقق الحكومي غير متاحين؛ كل وثيقة إصدار موسومة «تجريبية — غير صالحة للاستخدام الرسمي».
- حماية API الطلبات بحسب المالك والجهة؛ تحديث مشروط بالإصدار لمنع الكتابة فوق تغيير موظف آخر.
- تثبيت كتطبيق ويب وواجهة انقطاع اتصال. لا تُخزن صفحات الحسابات أو API في service worker.

## الخادم وقاعدة البيانات
نفس متغيرات شمال الموجودة في .env.example: DATABASE_URL أو POSTGRES_URL، وAUTH_SECRET، وإعدادات المزود اللغوي. تعطل الخادم لا يحوّل الحساب الحقيقي إلى حساب تجريبي.
تُنشأ service_requests وagency_members عند أول استخدام API الطلبات. الحسابات المسجلة تكون مستفيدين، ولا يمكن التسجيل الذاتي كموظف.
لتعيين موظف جهة: ينشئ المشرف المخول صفاً في agency_members في قاعدة البيانات بعد التحقق من الحساب والجهة:
```sql
INSERT INTO agency_members (user_id, entity_id, role)
VALUES ('EXISTING_USER_ID', 'mc', 'agency');
```
استخدم معرف جهة من src/lib/kb/entities.ts. الدور admin مخصص لإشراف المنصة. لا توجد واجهة إدارة عضويات الجهات في هذه النسخة.
طلبات البلديات تتضمن المنطقة والمدينة وتصل إلى صندوق البلديات المشترك؛ تخصيص موظفي كل بلدية على حدة يحتاج إضافة نطاقات عضوية إقليمية.

## حدود النسخة
هذه نسخة تجريبية متكاملة، وليست تكاملاً حكومياً معتمداً. قاعدة المعرفة الحالية موروثة من شمال: 23 خدمة و17 سيناريو و19 جهة/منصة، وليست حصراً لجميع الخدمات الحكومية السعودية. لم تُراجع الرسوم أو الأنظمة من جديد أثناء الدمج؛ المصادر وتواريخ التحقق موجودة في بطاقات الخدمات.
الاستفسار لا يتطلب مستنداً. طلب الترخيص المحدد يستخدم متطلبات الخدمة؛ الطلب العام يترك تحديد المتطلبات التفصيلية للجهة.
التحليل بدون مفاتيح مزود يعمل بالكلمات المفتاحية ويُصرح بذلك. تجهيز الربط بمزود لا يعني اختبار جودة النموذج الفعلية.
الإشعارات حالياً تحديثات داخل المنصة؛ لا توجد رسائل SMS أو إشعارات دفع. التصعيد يدوي عند تجاوز المهلة، ويظهر للإشراف؛ لا توجد مهمة تصعيد آلية مجدولة.
قبل تشغيل بيانات حقيقية: اعتماد الجهات، مراجعة المتطلبات، ضبط العضويات، تخزين ملفات مستقل، وحدود استخدام موزعة لمزود الذكاء الاصطناعي.
